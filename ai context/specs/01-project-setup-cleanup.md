# 01: Project Setup & Cleanup

Status: ✅ Complete

## Goal

Transform the currently-inherited expense-tracker Expo codebase into a clean BikeLog mobile foundation: strip domain-specific code (routes, components, types), keep+adapt shared infrastructure, apply the one deliberate axios-interceptor fix, delete scaffold leftovers, update app identity, and build the real `COLORS` theme. This is the prerequisite for every screen that follows.

## Context

**Important discrepancy from stale docs**: `progress-tracker.md` claims "nothing has been built yet, no `app/`/`components/` folder exists." The app folder actually contains a full, unmodified copy of a different Expo project (found on disk at `00 own /expenseTracker2/client`, not the `expenseTrackerReactNative` path the older docs assumed — that exact path doesn't exist on disk). So this spec is not "scaffold from zero," it's "cleanup the inherited code." Per `ai-workflow-rules.md`'s Documentation Sync rule, this drift is noted here rather than repeated a third time across sibling projects.

**Stack and infrastructure to keep/adapt** (from `../PLAN.md` §2–§4, verified in the inherited codebase):

- Expo SDK 54 + expo-router (file-based routing).
- react-native-paper UI kit, plain `StyleSheet.create()`.
- TanStack Query v5 via `hooks/useApi.ts` (`useFetchData` / `usePost` / `usePatch` / `useDelete`, drop the unused `useUpdateData` for PUT routes — `bikelog_server` has no PUT endpoints).
- axios with `utils/axiosInstance.ts` configured + interceptors.
- `@react-native-async-storage/async-storage` for auth token + user JSON persistence.
- React Context (`context/user.context.tsx`) for auth state, not Redux/Zustand.
- `@expo/vector-icons`, `react-native-toast-message`, `react-native-gesture-handler` (Swipeable), `react-native-keyboard-controller`, `date-fns`, `Alert.alert`.

**The one deliberate axios-interceptor fix**: `utils/axiosInstance.ts` in the inherited project has a critical bug in the response interceptor's error branch — it does `return error;` instead of `return Promise.reject(error);` on failure, swallowing rejections. This means axios calls "succeed" even on HTTP errors, breaking catch-block error handling. Must be fixed by porting `bikelog_client-web-/utils/axiosInstance.ts`'s error-handling shape (normalize to a flat `{statusCode, message, errors}` object and actually reject), keeping the inherited project's request-interceptor (token attach from AsyncStorage) and 401-redirect logic as-is.

**Code to strip** (per `../PLAN.md` §8, the inherited "don't copy" list):

- **Expense-tracker domain routes/components/types**: `app/(tabs)/*` routes (`addTransaction.tsx`, `smart-add.tsx`, `monthlyTransactions.tsx`, `weeklyTransactions.tsx`, `history.tsx`), `app/modal.tsx`, `components/main/AddTransaction/`, `components/main/HistoryPage/`, `components/main/Home/`, `components/main/MonthlyTransaction/`, `components/main/weeklyTransactionsPage/`, `components/main/smartAdd/`, `components/main/shared/TransactionCard*`, `components/main/shared/TotalBalanceCard*`, `types/Transaction.tyes.ts` (includes the filename typo this spec must not propagate into new types).
- **Scaffold leftovers unused by real screens**: `components/themed-text.tsx`, `components/themed-view.tsx`, `components/parallax-scroll-view.tsx`, `components/external-link.tsx`, `components/hello-wave.tsx`, `components/haptic-tab.tsx`, `constants/theme.ts`, `hooks/use-color-scheme.ts`, `hooks/use-color-scheme.web.ts`, `hooks/use-theme-color.ts`.
- **Unused dependency**: `@react-native-picker/picker` is declared in `package.json` but never imported anywhere in the inherited app (grep-verified) — leave it in `package.json` (it'll be used by spec 02's Picker decision), but don't assume it's a proven pattern just because it's listed.

**Files to keep and adapt**:

- `context/user.context.tsx` — ported ~verbatim from the inherited project, holds `user`/`token`/`isLoading`, hydrates from AsyncStorage, exposes `handleSetUser`/`handleSetToken`/`logoutFunction`. Don't upgrade toward a heavier auth library; `bikelog_server` has no refresh-token flow to build against (same constraint the web app documented).
- `utils/AuthGuard.tsx` — ported ~verbatim, session gate wrapper for routes.
- `utils/api.ts` — keep `apiGet/apiPost/apiPatch/apiDelete`, **drop `apiPut`** (no PUT routes in `bikelog_server`).
- `hooks/useApi.ts` — keep the hook shape (`useFetchData<T>`, `usePost`, `usePatch`, `useDelete`), drop any references to `useUpdateData` or `apiPut`.
- `utils/colors.ts` — the `THEMES` object structure is reusable, but the inherited project's 4 unused alternates (coffee/forest/purple/ocean) and expense/income keys won't work for Bike Log. Build exactly one new theme (replacing `coffee` as the active one, or pick a new name) with Bike Log-specific colors: drop expense/income keys, add status-color keys for badge variants (`open`/`resolved` for issues, urgency levels for accessories, etc.). See `../ui-context.md` for styling conventions (no formal scale, literal numbers per component; radius 6–25; typography system font, no custom fonts; both iOS shadow + Android elevation on every card; currency `৳` prefix).
- `utils/AuthGuard.tsx`, `components/ui/`, `hooks/use-color-scheme.ts` (keep the scheme detection logic for potential future dark mode, even though not currently wired).

**App identity updates**:

- `app.json`: change `"name"` and `"slug"` to `"BikeLog"` if not already done. Fix `android.package` from `"com.moniruzzaman3018.ExpenseTracker"` to something like `"com.moniruzzaman.bikelog"`.
- `README.md`: replace the default `create-expo-app` boilerplate with a one-paragraph description of what Bike Log is (a motorcycle fuel/maintenance/spending tracker).

## Implementation

Test by reviewing the final file and confirming: (a) error path does `return Promise.reject(...)`, not `return error;`; (b) 401 responses still redirect via `router.replace("/auth")`; (c) token attach happens before request sends.
